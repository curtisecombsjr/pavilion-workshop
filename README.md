# Pavilion Workshop

A hands-on workshop introducing **[Pavilion 2](https://pavilion2.readthedocs.io)** — a
YAML-driven test framework for HPC systems — with a **slide deck plus a dozen live demos**
run on a real PBS cluster. Everything here is **verified working end-to-end**.

Repo: <https://github.com/curtisecombsjr/pavilion-workshop>

## The deck

- **`deck/pavilion-workshop.pptx`** is the deliverable — **upload it to Google Slides**.
- It's generated by **`deck/build_deck.py`**, whose content is a plain `SLIDES` list. Edit an
  entry (each is a `title` / `section` / `bullets` / `code` / `demo` dict, with optional `notes`
  for speaker notes) and re-run to regenerate:

  ```bash
  python3 -m venv .venv
  .venv/bin/pip install -r requirements.txt
  .venv/bin/python deck/build_deck.py      # writes deck/pavilion-workshop.pptx
  ```

  Styling is kept deliberately simple so Google Slides imports it cleanly. YAML on code slides
  uses expanded **block** style (dashes), not condensed flow style, for readability.

## The demos

Twelve one-command scripts, each mapped to a slide. Every `pav run` goes through **PBS** and is
followed by `qstat -a` to prove the scheduler dispatched it. See **[`demo/README.md`](demo/README.md)**
for the full run-of-show. Short version:

```bash
ssh root@pbs-server        # keyed, no password
sudo -iu pavilion          # pav config lives in pavilion's home — the -i matters
cd ~/pav_demo              # the deployed run-scripts
./01-basic.sh              # … through ./12-salog.sh
```

The demo ladder: basics (PASS/FAIL) → result parsing → permutations → PBS scheduling → modes →
series → custom command plugins → result loggers (CSV, saLog, OpenSearch→Grafana, MySQL) →
searchable run history.

## Configs & plugins

- **`configs/`** — the test/mode/series YAML, deployed into
  `~/pavilion2/config/{suites,modes,series}` on the cluster. See [`configs/README.md`](configs/README.md).
- **`plugins/`** — all the custom plugins shown in the workshop: result loggers
  (`result_output/`: csv_file, sa_log, opensearch, mysql) and command plugins
  (`command/`: hello, recent, test_summary, disk_usage). See [`plugins/README.md`](plugins/README.md).

## Notes

- **L6 (series):** run it on its own, not immediately after another heavy demo, and give it ~30s.
- **L9 (OpenSearch):** no setup needed — the read-back loads its password automatically (L8/CSV is a safe fallback).
- If a compute node goes `down: communication closed`, `systemctl restart pbs` on that node (or
  hard-reset the VM from the dev host).
